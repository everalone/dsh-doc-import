# ADR 0002: 消息中只放紧凑文件引用，正文经 read_document 按需回读

- 状态：已采纳
- 日期：2026-09-04
- 取代：[ADR 0001](./0001-inline-text-over-document-block.md)

## 背景

ADR 0001 把解析全文内联进用户消息。真实使用（长 PDF）暴露两个问题：消息在对话里
刷屏，且全文占用大量模型上下文。用户期望 Codex 式体验——对话里出现的是**文件本身**
（文件卡片），内容按需读取。

## 决策

- 消息文本只携带紧凑引用：`[document 名称, 类型, N 页, M 字符, id: <sha256>]`，不含正文。
- 模型通过 `read_document` 工具按 id 回读全文（工具在 ADR 0001 中已有）。
- 客户端渲染层（preview.ts）在**显示时**把引用原地升级为文件卡片（图标+文件名+元信息），
  点击打开弹窗：默认展示全文（`/doc-import/status`），并提供"打开原始文件"
  （`/doc-import/raw/<id>`）在新标签页打开原文件。底层消息文本不变，会话日志与模型侧不受影响。
- 解析/OCR/存储管线不变；费用提示由导入时的文档卡片承担（发送不再有内联费用提示）。

## 备选方案

1. **维持全文内联**（ADR 0001）：显示与上下文成本随文档大小线性增长，已被实测否决。
2. **混合模式**（小文件内联、大文件引用）：多一条分支与一个阈值，用户体验不连续；用户明确选择纯引用。

## 后果

- 消息体积与文档大小解耦；转录区干净。
- 依赖模型主动调用 `read_document`——引用行与工具描述已明确指引。
- `inlineCap`/`costNoticeThreshold` 设置字段暂时仅作保留（未来若恢复内联路径可复用）。

## 修订（2026-09-05）

- 引用行后允许附加一句模型可见的固定引导语（"如需全文，调用 read_document 工具并传入
  上面的 id…"）。实测（commit 753a3fa）中，缺少该句时模型曾把 id 当作文件路径全盘搜索，
  冻结会话；引用行 + 工具描述双保险仍不足，故在本 ADR 框架内明确：紧凑引用包含这句引导语，
  仍不含正文。
- 内联模式残骸（showCostToast、toast.* 文案、发送钩子阈值参数、package.json 过期描述）
  已在本修订中移除；`inlineCap`/`costNoticeThreshold` 字段按上文"暂时保留"继续保留。
