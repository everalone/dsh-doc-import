# 路线图

## 已完成

**v1（首个可用版本）**

- [x] 拖入/粘贴/选择导入 txt / md / csv / docx / pdf，host 端解析与存储（内容寻址）
- [x] 扫描版 PDF 逐页自动 OCR（`deepseek-v4-flash-vision-exp`，页数上限/并发/重试护栏）
- [x] 纯文件引用进消息（ADR 0002）：对话渲染文件卡片 + 全文预览弹窗 + 打开原始文件
- [x] `read_document` 工具按 id 回读全文；设置卡（可折叠，三组配置 + 价格表）
- [x] PDF 文本层提取 v2：全局 (y,x) 视觉排序 + 行聚类 + 分栏检测 + 旋转排除
      （不再信任内容流顺序；单栏与简单两栏版式顺序正确）

**v1.1（稳定性与官方环境）**

- [x] 官方环境一等公民：不装社区全家桶也能用（设置卡走官方「插件配置」页）
- [x] OCR 可观测、可恢复：输出截断自动加倍重试并标注；失败页保留待办，重导只补失败页；
      作业必有终态（就绪/失败）不挂起发送；崩溃自愈重启有持久化次数上限与退避
- [x] `read_document` 支持 `offset` 分页 + `totalChars` 回报，长文可翻页读完
- [x] 每页 `[第 N 页]` 标记 + docx 图片去噪 + CSV 全文入库（`EXTRACTOR_VERSION` 3 → 4）
- [x] 引用行自带 shell 可读路径（锚定预设首轮只有 bash 时可直接 `cat` 全文）
- [x] 客户端健壮性：草稿跨会话/跨刷新保留（ADR 0003）；状态更新即时重渲染；
      给模型看的引导语不在 UI 显示

## 下一步（v2 方向，按优先级）

1. **复杂页视觉重提取**（重点，效果/成本比最高）
   - 判定"复杂页"：分栏检测失败、版面碎片密度异常、表格密集的页
   - 把复杂页渲染成图 → `deepseek-v4-flash-vision-exp` 输出 **Markdown**
     （标题层级、表格、阅读顺序由模型理解）
   - 复用现有 OCR 通道：只改"复杂页判定"与"提取 prompt"
   - 成本：每页约 384 图 token + 输出（≈¥0.01/页），受现有价格护栏约束；
     文本层干净的页继续免费直提
2. **离线专业版面引擎**：pdfplumber（Python/MIT）或 poppler `pdftotext -layout`
   （GPL CLI）作为可选引擎，块级文本 + 真实阅读顺序；引入外部运行时依赖
3. **纯 JS 版面分析**：pdf2json（Apache-2.0）块级输出 + 自研 XY-cut 阅读顺序
4. OCR prompt 升级：逐字转录 → 结构化 Markdown（表格/标题/列表）

## 可选集成

- **与 dsh-better-sidebar 互补**（已核实其为"工作台 / 文件视觉预览"定位，不做内容解析、OCR
  与文档内容摄入，不能平替本插件）：该插件客户端导出 `ctx.betterSidebar.registerTab` /
  `registerFileViewer`，可增量注册一个侧边栏标签页或文件查看器，展示本插件提取的全文
  （或提供"在侧边栏打开"入口）。纯新增代码，不需要改动现有实现。

## 可选打磨

- **延期格式**：`.doc`（旧二进制）、`.xlsx`、`.pptx`、`.rtf` 尚未支持（v1 只承诺
  txt/md/csv/docx/pdf）；解析器是注册表，新增格式为纯增量
- 文档卡片显示 OCR 状态徽标；历史消息的文件卡片在插件禁用时优雅降级
- 同一文件多会话共享的引用计数清理
- 更大上传的流式分块上传
- 发布到 npm 以支持 `dsh plugin --profile web add dsh-doc-import` 一键安装（用户暂缓）
